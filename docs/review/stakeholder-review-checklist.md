# Stakeholder Review Checklist

## Review Roles

- Founder / product owner.
- Frontend developer.
- Designer / brand reviewer.
- Tutor / education reviewer.
- Parent-like reviewer.
- Investor-facing reviewer.

## Review Items

| Area | Check |
|------|-------|
| Product path | Can a reviewer explain the student -> teacher support -> parent visibility loop after the demo? |
| Visual quality | Does the product feel premium, calm, and education-focused? |
| Multilingual quality | Do English, German, French, and Italian read naturally on core pages? |
| Development residue | Is normal UI free of demo/mock/provider/Codex/development wording? |
| Demo stability | Can the demo be reset and repeated without manual data repair? |
| Contact/footer/logo | Do brand/contact details feel real and trustworthy? |
| Learning Assistant language | Does first-response help sound supportive without overclaiming? |
| Professional teacher support | Does tutor escalation show teachers remain part of the process? |
| Parent report | Does the report provide useful visibility without alarmist language? |
| Pricing | Does pricing feel prepared but not overpromised? |
| Admin/operations | Does admin visibility support the demo without exposing unfinished internals? |

## Result Classification

- Approved: Ready for launch-candidate branch after final checks.
- Approved with minor fixes: Ready once listed minor fixes are complete or accepted as known issues with workaround.
- Needs revision: Important issues remain; return to bug-fix cycle before launch-candidate branch.
- Blocked: A P0 issue prevents demo or launch-candidate approval.
