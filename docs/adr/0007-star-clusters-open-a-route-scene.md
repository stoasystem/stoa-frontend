# 星图聚成星团，点星团进路线场景、不再飞近

2026-11-25，用户在本地样稿上确认（stoasystem/stoa-frontend#747）：一个学科的星不再按 topic 散成许多星云，而是聚成几个大星团；全景只看星团，不显示星的内容；在全景点一个星团，进入这一团的**路线场景**（从左到右的一条主线，每列最多三条支线），不再像以前那样把镜头飞近那团星云、弹出星卡片。原因是星多了以后满天的星和星名太乱，学生几乎没法在全景里手动找到要练的那颗；路线把「先学什么、后学什么」直接摆出来。

## 和 ADR 0001（一片星空）的关系

不推翻。所有学科仍在同一片天空里，星系、星形、连线、星团云的画法不变，跨学科前置照旧画在天空上；只是「星云」这一层换成了星团（一个星团是几个 topic 合起来的一朵云），全景的点击换了去处。路线场景盖在星图上，星图一直挂着、停在学生离开时的视角，返回就是回到那里，所以学生仍是在**一张**星图里进出，而不是换到另一张图。放大之后的星图（点星、点星云、星卡片、连线分层）与以前一样。

## 决定

- **星团划分**：前端一张映射表（`src/features/starmap/route/clusters.ts`），topic → 星团，四语名字；表里没有的 topic 各自成团。数学四团；2026-11-26 起物理三团、德语四团、英语四团也进了表（英语三个主题团的星彼此几乎不依赖，德语有三团是两个互不相干的 topic 合成的，这六团的主线用人工列表：按 topic、topic 内按星的 `order` 排成一条线，每颗星都在主线上）。
- **布局不看学习状态**：主线是团内前置关系的最长链（可用人工列表覆盖），其余点贪心排进支线；跨团前置收成入口。同一份数据永远得到同一条路线、同一片星空。读模型的 `placed()` 用 `layoutClusteredSky` 摆星，星的 `nebulaId` 换成星团。
- **全景**：离最远缩放 `REVEAL.panoramaBand` 以内不出星名、悬停不点出星，团名常显；放大后按原来的语义缩放出现。
- **点星团**：全景下点星团、团名或团里的星，或键盘 Tab 到星团链接按 Enter，进 `/map/:subjectId/cluster/:clusterId`，不带 `?star=`、不弹卡片，滚到推荐点。`?star=` 用于从别团的入口过来时定位到那颗星。

## Considered Options

- **保持飞近星云、只把星云合并成星团**：星团里一次有二三十颗星，飞近之后还是一片星名，「下一步学什么」仍然要自己找。否决。
- **路线场景做成单独的页面**：星图卸载，返回时要另存、另恢复镜头，还会重放落点、提醒等进入星图时的流程。否决；场景和星图同一个页面组件，星图在下面不动（`inert`）。
- **星团划分交给后端**：更对，但现在没有后端字段，先放前端；以后要不要让读者接口带星团字段另开票。

## Consequences

- 以 topic 构造的星图链接（章节、Ask、点亮时刻）里的 topic 不再是星图上的星云：`resolveTarget` 把 topic 映到它的星团，找不到就按链接里那颗星自己所在的星团。
- #123 定的「全景只画悬停的那团星云名」改为「全景每团都有名字」。
- 推荐点常不在主线上、几何团拥挤、手机上卡片挡住下方车道，都先按默认留着，见 #747「还没定」。
