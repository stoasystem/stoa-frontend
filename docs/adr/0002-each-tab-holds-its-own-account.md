# 每个标签页各自绑定账号，取消共享 token

2026-10-17，#216、#217 的决议：多账号是真实的产品功能（家长和孩子共用一台电脑、老师有工作账号和个人账号），底线是**已经有身份的标签页不能被静默换成另一个账号**。原来的模型是：未固定的标签页每次请求都现读 localStorage 里共享的那一对 token，只有「切换账号」才把标签页固定到 sessionStorage。在这个模型下，别的标签页一登录、加账号，或者固定标签页登出、过期，就会让某个标签页换了人，而界面还显示原来的用户。所以取消共享 token，每个标签页各自持有自己的凭据。

## 规则

- 换账号只能来自本标签页里明确的登录、切换或加账号。跨标签页的操作可以让本页退出或要求重新认证，但不能让本页切换账号。界面显示的身份必须与请求实际使用的身份一致。
- 刷新、恢复、复制标签页都保留绑定，也保留退出状态。
- **新标签页初始化**：可用的保存账号有 0 个时显示登录页，1 个时直接绑定，多个时显示账号选择页。没有「默认账号」。
- **登录结束后**（主动登出，或者续期被明确拒绝）：标签页进入「登录已结束」状态，按登出的标准清理本地业务状态，只保留原来的身份（用于提示和预填）和经过校验的返回地址。不会退回任何其他账号，刷新也不会。网络不通、超时、5xx 不算登录结束。
- **主动登出**会让持有同一次登录（`origin_jti`）的其他标签页一起退出，不按账号或邮箱匹配。
- **一次性迁移**：以前固定过的标签页保留绑定；旧的共享凭据只补进保存列表里缺的项，然后弃用；旧的未固定标签页按新标签页的规则初始化，不保证还是原来的账号（当时生产上只有测试账号）。

## Considered Options

- **保留共享账号，监听 `storage` 事件来察觉变化**：仍然是别的标签页决定本页是谁，只是从静默变成被打断。否决。
- **保留固定 / 未固定两类标签页，只修具体路径**：未固定标签页之间仍然会互相换人。否决。
- **过期后回到共享账号并提示**：这就是 #217 的问题本身。否决。
- **新标签页用「最近登录」或「最近使用的标签页」的账号作为默认**：在共用电脑上，从孩子的标签页新开一页，会进入家长账号。宁可多一次选择。否决。
- **刷新时按 `reload` 推断旧未固定标签页原来的身份**：接过来的可能正是被覆盖过的账号。否决。

## Consequences

- 同一次登录开在多个标签页里时，各标签页各自续期（Cognito 的续期令牌不轮换，两份副本可以并存）。
- 保存的账号仍然可以一键进入。这条决议防的是静默换人，**不**提供家庭成员之间的访问隔离；那一块在 #229 讨论。
- 实施见 #230 → #231 → #232。三张票在集成分支上一起完成，独立审计后再合回 `main`，中间版本不上线。
