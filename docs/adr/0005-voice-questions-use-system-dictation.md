# 语音提问只靠系统自带听写

2026-10-23，「浏览器语音输入」（stoasystem/stoa-frontend#494）调研后决定：STOA 不写任何语音识别代码，只在提问框旁用四种语言教孩子用设备自带的听写（Windows `Win + H`、Mac 的麦克风键、手机和平板键盘上的麦克风），并在隐私说明里写明「语音由你设备的系统处理，STOA 只收到文字」（#515）。原因是用户是未成年人：网页里的麦克风按钮会让浏览器把录音送到 Google、微软或 Apple 的服务器，STOA 要为这段收集和传输负责，却无法与这几家签数据处理协议；只有孩子自己用系统听写时，录音才完全不经过 STOA，不新增义务。

## Considered Options

- **网页里的麦克风按钮，用浏览器自带的语音识别**：默认模式下 Chrome 把录音送到 Google、Edge 送到 Azure、Safari 送到 Apple；按欧盟法院 Fashion ID 案的思路，触发它的网站要对收集和传输负责。Firefox 正式版也不支持。否决。
- **只在浏览器能在本机识别时才显示按钮**（Chrome 桌面版 139 起的 `processLocally`）：录音不出设备，但目前只有这一个浏览器，语言包也只有 de-DE / fr-FR / it-IT / en-US，没有 -CH。暂缓；以后做网页按钮只走这条路，不用云端模式。
- **后端转写**（AWS Transcribe，苏黎世区域有端点）：STOA 自己接收和处理孩子的录音，要家长同意等新义务；只有 de-CH，没有 fr-CH / it-CH。否决。

## Consequences

- STOA 只收到文字，没有录音要存、要删、要审核。
- 数学式子说出来的转写质量很差（公开数据里字符错误率约三成），语音只适合说卡在哪，不适合念公式；孩子写不出式子的问题，留给「公式输入辅助」，重启条件见 #492。
- 瑞士德语方言的识别效果没有公开数据，系统听写听不懂方言时，STOA 没有办法补救。
