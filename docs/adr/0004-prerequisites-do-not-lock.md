# 前置不再锁住知识点

2026-10-22，「推定掌握的规则」（stoasystem/stoa-frontend#473）讨论时决定：所有知识点默认都能学，前置只是建议，不再拦学生；学习状态从四种减为三种（点亮、进行中、可开始），「锁定」降为叠在状态上的标记**前置未点亮**。原因有两个。第一，锁定下学生只能先点亮全部前置，才点得亮后继，「点亮一颗星就推定它的前置已会」一颗也推不出来，推定掌握的整套规则落了空。第二，新生没法从课程中段开始学，录屏里的「学完三角函数」在真实规则下根本走不到（#469）。

## Considered Options

- **保留锁定，先定推定掌握**（#473 原题）：要让推定生效，还得先做越过锁定的途径（整颗星的跳过测验 #475、锁定目标星的路径 #478），三张工单串成一条长链，才换来最多 5 个 unit 的推定（#470）。暂缓，整题移入 #469 的 Not yet specified。
- **锁定只留在界面上，后端照常拒绝**：请求会被 `lesson_locked` 拒绝，等于没改。否决。
- **保留「锁定」这个状态名，但点进去照样能学**：词和行为相反。否决。
- **做成开关，默认解锁**（例如老师可为某个学生重新上锁）：替尚未提出的需求写代码。否决；要不要、由谁恢复锁定，留在 #469 的 Not yet specified。

## Consequences

- stoa-backend 不再判出 `locked`，取消 `lesson_locked` 的拒绝，改为给知识点带出「前置未点亮」。
- 推荐标记仍按 #9 第 8 点取课程顺序上的第一颗可开始，而现在几乎每颗没碰过的星都可开始，推荐更容易落回课程开头；新规则由「点亮之后推荐谁」（#474）定。
- 「目标星是锁定的怎么办」（#478）的前提不再成立；整颗星的跳过测验（#475）不再是越过锁定的唯一途径。
- 以后若恢复锁定，推定掌握要一起重新讨论：它的意义就在于锁定。
