# 一个浏览器一个账号，取消保存的账号

2026-10-19，#229 的决议（用户决定），实施见 #320。取代 [ADR 0002](0002-each-tab-holds-its-own-account.md) 中「多账号是真实的产品功能」及由此而来的部分：保存的账号、账号切换、加账号、新标签页的账号选择页。0002 的底线保留：**已经有身份的标签页不能被静默换成另一个账号**，界面显示的身份必须与请求实际使用的身份一致。

理由（用户）：共用设备的安全由用户自己负责。浏览器本来就会问要不要保存密码，应用不需要再提供一键进入别人账号的功能；去掉它，「孩子点一下进家长账号」的问题也就不存在了，不用再设计重新认证（#229 的 Q1、Q2 随之作废）。

## 规则

- **浏览器只有一次登录。** localStorage 里记一条「浏览器登录」：一个随机 id、access token、refresh token、账号（邮箱、名字、角色，用于提示）。换人只能退出再登录；在任何标签页登录，就换掉这一条。
- **每个标签页仍然只发自己那份凭据。** 标签页把它加入的那次登录的 token 和 id 存在自己的 sessionStorage 里，请求只带这一份。加入只发生在：本标签页里登录；新标签页启动时；登录页上（这时标签页没有显示任何人的账号）。
- **跨标签页只能让本页退出，不能让本页换人。** 浏览器登录被结束或换掉之后，还在旧登录上的标签页立即退出（`storage` 事件），每个请求发出前也再核对一次（标签页休眠、错过事件时兜底）。退出时记下原来的账号和所在页面。
- **退出后的登录页：** 浏览器此刻没有登录 → 按 0002 的「登录已结束」页（说明谁的会话结束了，预填）；登录的是同一个人 → 直接加入并回到原来的页面；登录的是**别人** → 说明「另一个标签页现在登录的是 X」，用户点「以 X 继续」才加入，也可以改用别的账号登录。主动退出过的标签页、新标签页不记得任何人，直接加入。
- **已登录时打开登录页直接进入应用**（加入浏览器登录）。
- **主动退出、续期被拒** 都结束浏览器登录，所有标签页一起退出。网络不通、超时、5xx 不算。
- **刷新、恢复、复制标签页** 保留它所在的登录；如果期间浏览器登录已经被结束或换掉，它启动时就退出，按上面的登录页规则处理。
- **被换掉的登录在服务端结束**：新的登录替换旧的浏览器登录时，用现有的 `POST /auth/logout` 结束旧的那次登录（access token 已过期时先用 refresh token 续一次再登出）；角色切换器保留的测试角色除外。尽力而为，不重试，不影响本地。

## 一次性迁移

上线后每个浏览器第一次启动新代码时：保留一次登录——已有浏览器登录就保留它，否则保留当前标签页的，否则只有在保存列表里只有一个人时保留他最近的那次登录——写成浏览器登录。列表里有好几个人而没有标签页登录着时，谁也不保留，大家重新登录：共用电脑上最后保存的可能是家长，孩子的下一个新标签页不能不经选择就进入家长账号（独立审计 F6）。保存列表（`stoa_dev_sessions`）和 #216 之前的共享 token 全部删除；其他每个保存的登录都用上面的方式在服务端结束，所以旧列表里的账号（例如家长账号）再也点不进去。旧版本留下、不在保留登录上的标签页，下次启动或发请求时退出，它的那次登录也在服务端结束。不需要改后端。

## 测试角色切换器

`?roleswitcher=on` 才出现，而且只对 @test.stoaedu.ch 账号出现。它的列表单独存放（`stoa_test_roles`），写入和读出都只认测试域名的地址，所以真实账号永远进不了这个列表，迁移也不会往里放任何东西。切换到一个测试角色就是一次普通的浏览器登录：其他标签页退出旧角色；离开的那个测试角色会被保留在列表里，所以不在服务端结束它。

## Considered Options

- **保留 0002 的每标签页独立账号，只去掉保存列表**：新标签页就只能是未登录，「打开新标签页还是登录状态」做不到。否决。
- **回到所有标签页共读一份 token**：别的标签页一换人，本页下一个请求就以新账号发出，而界面还显示旧账号——正是 #217 的问题。否决；改为共享「浏览器登录」这条记录，但每个标签页只发自己加入的那份，并在不一致时退出。
- **别的标签页换人时，本页直接整页刷新成新账号**：等于静默换人。否决，改为退出并在登录页说明。
- **只结束本地凭据，不在服务端结束被丢弃的登录**：旧列表里的 refresh token 30 天内仍然有效。否决；现有接口能做到，就做。

## Consequences

- 同一次登录开在多个标签页里时，各标签页各自续期；续期后的 token 写回浏览器登录，新标签页拿到的是新的。这依赖 Cognito 的 refresh token 不轮换（0002 已经依赖这一点）；如果以后开启轮换，一个标签页轮换后，另一个标签页的续期会被拒，进而结束整个浏览器登录，需要重新设计。
- 浏览器登录这条记录的读改写不是跨进程原子的；两个标签页在同一毫秒里续期和登录，或者好几个旧版本标签页同时启动迁移，结果可能是所有标签页都退出。这些情况都是「退出」，不会显示错的人（独立审计 F4、F5），所以没有加锁。
- 共用设备上不再有一键进入别人账号的路径；访问隔离由用户自己负责（关浏览器、退出）。
- 0002 中「新标签页初始化：0 个 / 1 个 / 多个保存账号」「主动登出按 `origin_jti` 通知其他标签页」两条由本 ADR 的规则取代；「登录已结束」状态、刷新保留绑定、切换账号时不带走上一个账号的本地状态等仍然有效。
