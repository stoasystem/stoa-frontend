# Site Layout with Practice Entry

## Purpose

Phase 31 organizes STOA around a clear product hierarchy:

1. Practice Path helps students start learning.
2. Learning Chat explains when a step is unclear.
3. Professional teacher support helps when explanation is not enough.
4. Parent Report shows the complete learning activity.

Practice is visible, but it is not the public product identity and does not replace Learning Chat.

## Public Site

Public navigation should stay focused and not add Practice as a top-level navbar item.

- Home
- How it works
- Parents
- Teachers
- Pricing
- Q&A
- Contact
- Login
- Start learning

Practice appears on the homepage as a concrete learning example and as part of the STOA learning flow. It should not become a standalone public marketing island unless external testing shows that parents and students need a public Practice explainer page.

## Homepage Structure

Recommended order:

1. Hero: STOA learning support value.
2. Practice entry: start with short practice, continue with explanation.
3. Learning flow: ask, understand, teacher support, parent visibility.
4. Platform hierarchy: Practice, Learning Chat, teacher support, Parent Report.
5. Teacher support.
6. Parent visibility.
7. Trust and final CTA.

The homepage CTA hierarchy stays:

- Primary: Start learning
- Secondary: See how practice works / How it works

Avoid game-first wording such as Play now, Start game, Enter quest, gems, hearts, or shop.

## Student App

Student navigation:

- Dashboard
- Practice
- Learning Chat
- Learning History
- Profile

Student Dashboard priority:

1. Continue Practice
2. Open Learning Chat / Ask a Question
3. Recent learning activity
4. Teacher support status
5. Learning history

Practice and Learning Chat must be sibling actions with a clear relationship:

- Practice helps the student start.
- Learning Chat helps when a step or homework question needs explanation.

## Parent App

Parent navigation:

- Overview
- Reports
- Billing
- Contact

Parent surfaces should avoid separate Practice and Chat silos. The primary parent concept is Learning activity:

- Practice lessons completed.
- Questions asked.
- Steps explained.
- Teacher support requested.
- Recommended next focus.

## Tutor App

Tutor navigation:

- Requests
- Availability
- Support

Tutor Request Detail should show Practice context when relevant:

- Source: Practice lesson
- Topic
- Question
- Student answer
- Attempts
- Hint viewed
- Learning Chat explanation requested

The wording should say the student requested support after practising this step. Do not say the game failed.

## Q&A

Q&A remains a standalone categorized public page. Pricing should only keep plan-specific information.

Recommended Q&A categories:

- Student use
- Parent visibility
- Teacher support
- Pricing
- Account
- Support

## Wayfinding Rules

- Practice-to-Chat routes must show a Practice context card.
- Chat should show Back to lesson when lesson context exists.
- Lesson results should offer Review with Learning Chat, Review mistakes, and Continue Practice.
- Tutor detail should show Practice context before the general request transcript.
