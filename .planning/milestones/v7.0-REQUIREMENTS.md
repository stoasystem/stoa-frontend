# Requirements: STOA Frontend v7.0

**Defined:** 2026-07-07
**Core Value:** v7 must convert the existing STOA frontend into a full-site multilingual product across English, German, French, and Italian, with a documented language policy, role-aware tone rules, premium language controls, route-level QA coverage, and a legal/privacy research plan that is close enough for lawyer review without pretending to be final legal advice.

## v7.0 Requirements

### Scope, Language Policy, And Swiss Language Reality

- [x] **SCOPE-01**: Define v7 as full-site multilingual adaptation, not Home V2 switch-over, not a redesign, and not a new product-feature milestone.
- [x] **SCOPE-02**: Confirm launch runtime languages as English, German, French, and Italian.
- [x] **SCOPE-03**: Acknowledge Switzerland's fourth national language, Romansh, and document why runtime Romansh is deferred rather than forgotten.
- [x] **SCOPE-04**: Keep current `/` unchanged; `/home-v2` remains preview until a separate explicit switch-over program.

### Glossary, Tone, And Quality Rules

- [x] **COPY-01**: Create an initial terminology matrix for EN/DE/FR/IT with context notes and forbidden terms.
- [x] **COPY-02**: Preserve the product language decision to downplay raw AI wording in public copy while keeping the Learning Assistant concept clear.
- [x] **COPY-03**: Define role-based tone rules for public/parent, student, teacher/tutor, and admin/ops surfaces.
- [x] **COPY-04**: Define P0/P1/P2 translation quality tiers and review expectations.

### Runtime And Language Controls

- [x] **RUNTIME-01**: Plan runtime enablement for FR/IT across the app, not just translation JSON.
- [x] **RUNTIME-02**: Define Home V2's premium desktop language micro-control and mobile menu language chips.
- [x] **RUNTIME-03**: Define the general app `LanguageSwitcher` upgrade path for EN/DE/FR/IT without redesigning app pages.

### Route QA Matrix

- [x] **QA-01**: Define P0 routes requiring four-language screenshot QA.
- [x] **QA-02**: Define P1 route-smoke coverage for role surfaces and secondary workflows.
- [x] **QA-03**: Define P2 static and deep-route checks for admin, edge cases, legal, and internal-term cleanup.
- [x] **QA-04**: Require layout checks for long German words, French apostrophes, Italian CTA length, and mobile menu fit.

### Legal And Compliance Research Plan

- [x] **LEGAL-01**: Add a dedicated legal research phase covering Swiss FADP/DSG, GDPR relevance, minors/education data, privacy, terms, subscriptions, trial limits, refunds, cookies, retention, and user rights.
- [x] **LEGAL-02**: Define legal output as lawyer-review pre-candidate drafts, not final legal advice.
- [x] **LEGAL-03**: Document unknown facts needed before privacy/terms can become operationally usable.
- [x] **LEGAL-04**: Require EN source draft plus DE/FR/IT candidate legal translations with review markers.

### Program Handoff

- [x] **HANDOFF-01**: Split v7 into seven executable follow-up milestones: v7.1 through v7.7.
- [x] **HANDOFF-02**: Update planning state, roadmap, milestone index, and project documentation.
- [x] **HANDOFF-03**: Archive v7.0 planning artifacts and verify documentation diff hygiene.

## Out of Scope

| Item | Reason |
|------|--------|
| Replacing `/` with `/home-v2` | User explicitly decided not to replace `/` in this track. |
| Broad visual redesign | v7 focuses on multilingual adaptation and legal/copy readiness. Small layout fixes are allowed only when needed for language fit. |
| New product features | v7 should not add learning workflows, billing behavior, backend APIs, or role permissions. |
| Runtime Romansh | Acknowledged as a Swiss national language, but deferred until Graubunden/Romansh demand, budget, or legal requirement justifies it. |
| Final legal advice | The legal phase creates lawyer-review draft material only. |
| Paid legal certification | Requires external counsel. |
