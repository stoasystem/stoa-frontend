# Plan

1. Add role-specific onboarding components and `/onboarding` page.
2. Add support information components and `/support` page with FAQ, bug feedback, teacher-help distinction, contact path, pilot expectations, and a support request form.
3. Add typed support API service and TanStack Query mutation hook for `POST /support/requests`.
4. Wire `/onboarding` and `/support` routes in `AppRouter`.
5. Add onboarding/support links to authenticated app navigation.
6. Add operations documentation for triage, severity, ownership, response expectations, and backend compatibility.
7. Run TypeScript build and lint, then record verification.

## Acceptance Mapping

- ONB-01: `AppRouter` exposes `/onboarding`.
- ONB-02: Student onboarding content covers grade/subject setup and Chat entry.
- ONB-03: Parent onboarding content covers child dashboard and report visibility.
- ONB-04: Tutor onboarding content covers request list/detail/status workflow.
- SUP-01: `AppRouter` exposes `/support`, and `AppLayout` links to it.
- SUP-02: `SupportPage` includes FAQ, bug feedback, teacher-help distinction, contact path, and pilot expectations.
- SUP-03: `supportApi` and `useSubmitSupportRequestMutation` submit typed support payloads to `/support/requests`.
- SUP-04: `docs/operations/support-workflow.md` documents triage, severity, ownership, and response expectations.
