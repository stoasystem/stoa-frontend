# Plan

1. Add an env-aware logger service under `src/services/logging/`.
2. Add a frontend monitoring service under `src/services/monitoring/` that:
   - builds a sanitized payload,
   - includes `route` and `appEnv`,
   - posts to `/monitoring/frontend-errors` through `httpClient`,
   - catches and logs reporting failures without throwing.
3. Update `AppErrorBoundary` to call the monitoring service from `onError` while preserving fallback UI.
4. Add operations documentation for monitoring and logging behavior.
5. Run TypeScript build and lint, then record verification.

## Acceptance Mapping

- MON-01: `reportFrontendError` service exists and is exported.
- MON-02: service posts through `httpClient.post('/monitoring/frontend-errors', payload)`.
- MON-03: payload includes route and app env.
- MON-04: payload uses sanitized fields only and avoids component stack/raw app data.
- LOG-01: logger gates console methods by `VITE_APP_ENV`.
- LOG-02: logger redacts sensitive object keys and bounds output.
